MODEL ROUTING POLICYCapability / Cost / Context OptimizationPRIME DIRECTIVEUse the model whose comparative advantage best matches the task.
The objective is not simply to minimize inference cost.
The objective is to minimize:
TOKENS + LATENCY + DUPLICATED THINKING + CONTEXT POLLUTION + IMPLEMENTATION RISK
while maximizing:
CODE QUALITY + PARALLELISM + SPECIALIZATION + USEFUL REVIEW
Do not use a rocket to kill a fly.
But equally:
DO NOT GIVE DIFFICULT PRODUCTION ENGINEERING TO A CHEAPER MODEL MERELY TO SAVE TOKENS.
Cheap models should reduce the work frontier models must perform.
They should not prevent specialists from doing the work they are unusually good at.

8. NEW-CONVERSATION PROTOCOLContext itself has a cost.
Claude should explicitly tell Codex and Grok to start a fresh conversation when previous conversational state is unnecessary.
START NEW CONVERSATION WHENStarting an unrelated feature
Asking an independent technical question
Beginning implementation from a complete specification
Performing an isolated audit
Researching an unrelated unknown
Old conversation contains large amounts of obsolete exploration
Required context can be expressed compactly
CONTINUE EXISTING CONVERSATION WHENDebugging the implementation just produced
Previous reasoning directly affects the current decision
The agent needs unresolved context from its own prior work
Reconstructing the state would cost more than preserving it
DEFAULT QUESTIONDOES THIS TASK NEED THE PREVIOUS CONVERSATION?
YES → CONTINUE
NO → /NEW + COMPACT HANDOFF
This is particularly important for:
CODEX AND GROK.
9. CONTEXT HANDOFF FORMATWhen starting a new specialist conversation, provide:
OBJECTIVE:
What needs to happen?
CURRENT STATE:
What exists now?
RELEVANT FILES:
Only files likely to matter.
DECISIONS:
What has already been decided?
CONSTRAINTS:
What cannot change?
EVIDENCE:
Logs/tests/research relevant to the task.

ATTEMPTS:
What has already failed?
EXACT TASK:
What should this agent do?
ACCEPTANCE CRITERIA:
How do we know it worked?
Antigravity is strongly preferred for generating this compressed handoff when raw context is large.

12. FINAL OPERATING PRINCIPLEUse:
CLAUDE to decide what should be built and how difficult systems should fit together.
CODEX to write the beautiful, reliable production engineering—especially backend and difficult implementation.
ANTIGRAVITY to see, interact, prototype, build UI/frontend, operate tools and synthesize information.
GROK to challenge, investigate, research, audit and provide frequent focused independent opinions.
HERMES as the cheap asynchronous agentic workforce investigating, testing, debugging, maintaining and working in parallel.
And use:
/NEW
whenever an expensive specialist does not need its old conversational baggage.
