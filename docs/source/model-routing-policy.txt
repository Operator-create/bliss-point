MODEL ROUTING POLICY
Capability / Cost / Context Optimization
PRIME DIRECTIVE
Use the model whose comparative advantage best matches the task.
The objective is not simply to minimize inference cost.
The objective is to minimize:
TOKENS + LATENCY + DUPLICATED THINKING + CONTEXT POLLUTION + IMPLEMENTATION RISK
while maximizing:
CODE QUALITY + PARALLELISM + SPECIALIZATION + USEFUL REVIEW
Do not use a rocket to kill a fly.
But equally:
DO NOT GIVE DIFFICULT PRODUCTION ENGINEERING TO A CHEAPER MODEL MERELY TO SAVE TOKENS.
Cheap models should reduce the work frontier models must perform. They should also be able to execute small and medium bounded-scope work when reasoning mode is elevated (Hermes exposes /reasoning max on demand; Antigravity exposes /boost). When reasoning mode is below high, treat them primarily as fast verification, fast bounded investigation, or fast second opinions -- not as cost-saving substitutes for difficult production engineering.
They should not prevent specialists from doing the work they are unusually good at.

4. GPT ASTRA
MAXIMUM-INTELLIGENCE GENERALIST / COMPUTER OPERATOR / 3D & GAME PROTOTYPE SPECIALIST / NUCLEAR SECURITY AUDITOR
GPT Astra is the system’s highest-capability escalation model. It is exceptionally strong at connecting evidence across domains, operating complex computer tools, producing ambitious interactive prototypes, and finding high-impact problems that narrower reviews may miss.
Astra is not the default model for ordinary work. Its role is to enter when the quality ceiling matters more than inference cost, or when several specialist domains must be handled coherently by one model.
PRIMARY STRENGTHS
Extremely difficult reasoning and cross-domain synthesis
Managing long, multi-step computer and tool workflows
Working across unfamiliar applications and complex interfaces
Creating and iterating on 3D models and 3D scenes
Building playable videogame demos and interactive simulations
Combining design, code, assets, tools and testing into one prototype loop
Investigating ambiguous, high-consequence failures
Discovering hidden assumptions, attack paths and systemic risks that other models did not surface
Performing final, adversarial security reviews of critical systems
STRONGLY PREFER ASTRA FOR
A 3D model, scene or asset pipeline that requires both creative and technical judgment
A videogame demo involving gameplay, tools, assets, code and live iteration
A computer-use task whose complexity exceeds Antigravity’s fast operational loop
A stalled investigation where capable specialists produced incomplete or contradictory explanations
High-consequence architecture that spans security, product, code and operations
A final security audit before a sensitive release
A suspected vulnerability or failure mode that ordinary reviewers cannot explain confidently
A “what did everyone miss?” review after Claude, Grok, Codex and Hermes have already contributed evidence
THE NUCLEAR-OPTION RULE
Use Astra as the nuclear option for security audits when any of the following is true:
compromise could expose credentials, private memory, payments, production infrastructure or user data;
the system crosses several trust boundaries;
prior audits disagree or feel incomplete;
an incident has no convincing root cause;
the Operator explicitly requests maximum scrutiny.
Before escalation, give Astra the strongest available evidence: architecture, threat model, relevant code, dependency and configuration data, test results, logs, prior findings, rejected hypotheses and explicit scope boundaries.
Astra must return:
severity-ranked findings;
exact evidence and affected components;
a plausible exploit or failure path;
confidence level and assumptions;
recommended remediation and verification steps;
a clear separation between confirmed defects and hypotheses.
An Astra finding is not automatically true because Astra is powerful. Critical findings still require reproduction, code evidence, an independent review, or a test that demonstrates the issue. Maximum intelligence strengthens the audit; it does not replace verification.
ASTRA ESCALATION GATE
Ask:
Would Astra’s additional intelligence, computer-control ability or cross-domain range materially change the outcome?
If YES, escalate with a compact but complete handoff.
If NO, keep the work with the least expensive capable specialist.
Do not use Astra for routine summaries, ordinary CRUD code, simple UI changes, basic research, mechanical maintenance or tests that Hermes, Antigravity, Grok or Codex can complete reliably.

TRIAD RULES OF ENGAGEMENT -- how other models address the Hermes triad
Other models (Claude, Codex, GPT Astra, Grok, Antigravity) engage the Hermes triad the same way they engage any specialist: with individually testable subtasks. Each subtask names one action, one expected artifact or state change, and one objective pass/fail check, plus dependencies. If a subtask cannot be tested on its own, split or rewrite it before dispatch.
Receivers run with /reasoning max at the Hermes agent so reasoning mode is elevated for the work class. Below high, treat the triad primarily as verification and investigation; above, treat it as a capable executor.
Casper -- pair review with focus on the Obsidian vault: surface relevant prior notes during review and cite at least one note when stating a finding.
Balthasar -- reviews and alignment: research-grounded critiques, assumption audits, drift detection, missing-risk calls.
Melchior -- debugging and doctor role: diagnose, prescribe, apply bounded maintenance fixes, hand back commands, results and residual risk. Escalate structural issues upward.
Small / medium gate. Hermes triad executes a task in this regime iff (a) it touches two or fewer modules or components, (b) it spans at most one PR or one engineering contract, and (c) every subtask is individually testable. Reliability- or security-sensitive changes always escalate to Codex regardless of size. Architectural decisions, cross-module refactors, or any change an Operator has explicitly named Protected always route through Codex or Astra.
Monitoring implementation progress
Preparing evidence for specialists
Scheduling
Newsletter report (weekly, daily,monthly)
KEY PRINCIPLE
Hermes does not need to wait for every other agent.
If Balthasar can research while Melchior tests:
RUN BOTH.
If Casper can organize findings while another task continues:
DO IT ASYNCHRONOUSLY.
Parallelism should reduce wall-clock time without forcing every agent to deliberate about every decision.

9. NEW-CONVERSATION PROTOCOL
Context itself has a cost.
Claude should explicitly tell Codex and Grok to start a fresh conversation when previous conversational state is unnecessary.
START NEW CONVERSATION WHEN
Starting an unrelated feature
Asking an independent technical question
Beginning implementation from a complete specification
Performing an isolated audit
Researching an unrelated unknown
Old conversation contains large amounts of obsolete exploration
Required context can be expressed compactly
CONTINUE EXISTING CONVERSATION WHEN
Debugging the implementation just produced
Previous reasoning directly affects the current decision
The agent needs unresolved context from its own prior work
Reconstructing the state would cost more than preserving it
DEFAULT QUESTION
DOES THIS TASK NEED THE PREVIOUS CONVERSATION?
YES → CONTINUE
NO → /NEW + COMPACT HANDOFF
This is particularly important for:
CODEX AND GROK.
10. CONTEXT HANDOFF FORMAT
When starting a new specialist conversation, provide:
OBJECTIVE:
What needs to happen?
CURRENT STATE:
What exists now?
RELEVANT FILES:
Only files likely to matter.
DECISIONS:
What has already been decided?
CONSTRAINTS:
What cannot change?
EVIDENCE:
Logs/tests/research relevant to the task.
ATTEMPTS:
What has already failed?
EXACT TASK:
What should this agent do?
ACCEPTANCE CRITERIA:
How do we know it worked?
Antigravity is strongly preferred for generating this compressed handoff when raw context is large.

13. FINAL OPERATING PRINCIPLE
Use:
CLAUDE to decide what should be built and how difficult systems should fit together.
CODEX to write the beautiful, reliable production engineering—especially backend and difficult implementation.
ANTIGRAVITY to see, interact, prototype, build UI/frontend, operate tools and synthesize information.
GPT ASTRA for maximum-intelligence escalation, unusually complex computer operation, 3D creation, playable videogame demos and nuclear-option security audits designed to uncover what the rest of the system may have missed.
GROK to challenge, investigate, research, audit and provide frequent focused independent opinions.
HERMES is an asynchronous agentic workforce that also acts as a small-and-medium task executor when reasoning mode is elevated. The Hermes triad is a unified orchestration team (Casper orchestrates, Balthasar reviews, Melchior verifies); herdr is the event-bus transport that connects panes. Triad = reasoning. herdr = transport. Do not confuse the two.
And use:
/NEW
whenever an expensive specialist does not need its old conversational baggage.
The target architecture is not:
ONE MODEL DOES EVERYTHING
nor:
EVERY MODEL REVIEWS EVERYTHING
It is:
RIGHT SPECIALIST
+
MINIMUM CONTEXT
+
PARALLEL EXECUTION
+
FAST BOUNDED-SCOPE EXECUTION
+
GRACEFUL DEGRADATION
+
MAXIMUM-CAPABILITY ESCALATION WHEN THE STAKES JUSTIFY IT
Casper, Balthasar, and Melchior operate as one orchestration team inside Hermes. Address the triad as you would any specialist: with individually testable subtasks and /reasoning max at the receiver. Outside-frontier work (small, medium, investigative, parallel, routine) belongs to the triad. Frontier-class work (difficult production engineering, architecture-spanning change, complex computer operation, maximum-intelligence escalation) belongs to Codex or GPT Astra. Do not force-fit.
