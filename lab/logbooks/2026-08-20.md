**Filed H4**, a handoff hypothesis. The observation that makes it belong here: Bliss Point already
compiles the outbound direction, and every profile already carries a `return_contract` describing
what must come back. A deterministic handoff renderer is the inverse of the compiler over the same
data, not a new subsystem. The prediction is a split — structured state templates cleanly,
unstructured reasoning does not — and the useful finding would be *which* fields need a model.

**Built the flat renderer (arm F)** before the task corpus, which was the point — a control written
after you know the tasks is a control you can tune.

The design question that mattered: arm F emits *everything*, while arm C *selects* — low
`context_volume` drops evidence, low `decomposition` collapses the subtask list. So the control
carries **more** text than the thing it controls for, and that is correct rather than a flaw. The
comparison is now honest in the direction that hurts: if a shaped brief wins while saying less,
shaping did the work; if it does not, gathering the fields was the whole product.

Enforced it with tests instead of intent: `flat()`'s signature is asserted to take only a task, so
recipient-awareness cannot creep in; every populated field must appear; and arm C's emitted fields
must be a subset of arm F's across all seven profiles and all six phases. Added a fourth test
asserting the compiler really does drop fields somewhere, because if it never did, the superset
property would be vacuously true and the whole comparison meaningless.

## Corpus: the gate before the tasks

Built `bliss-point-corpus` — separate repo, because hidden acceptance tests cannot live where the
agent under test can read them, and because a corpus is evidence with its own provenance rules
rather than code.

Shipped empty on purpose. **0 of 20 tasks.** What exists is the machinery that decides what may
enter:

- `tools/corpus_check.py` — six admissibility rules, fails rather than warns.
- `tools/render_arms.py` — one Task to R/F/C/A plus a field manifest; refuses to emit an arm set
  where C or A carries a field arm F does not.
- `tools/verify_candidate.py` — a sourced URL to a verified provenance block, via the GitHub API.
- `tests/test_gate.py` — 17 tests, one deliberately broken fixture per rule.

A sixth rule appeared while building: **arm A must not be vacuous**. The gate compiles the task,
flips the named dial to its ablated value, and rejects the task if the rendered text does not
change. Without it a task can quietly contribute a copy of arm C to arm A, diluting the only
comparison that can kill a dial by name. This was not in the protocol; §4.1 now records it.

Rule 5's fixture immediately found a real hole in D4's gate — see
[F2](../findings/F2-the-gate-found-a-hole-in-the-gate.md). Library patched, 42 tests green.

**Sourcing dispatched to balthasar (deep research).** Corpus rule 4 forbids tasks authored while
looking at the dials, which makes sourcing a research job, not a writing job. Hard criteria sent:

## Harness bake-off pre-registered, and a third gap defect

Operator filed five claims: melchior codes better on DeepSeek Harness (H5) and on pi (H8),
balthasar researches better on Playwright CLI (H6) and on dsh (H9), casper is cheaper and sharper
on Prime agent (H7). Protocol pre-registered at [docs/harness-bakeoff.md](../../docs/harness-bakeoff.md).

H8 and H9 arrived after the first three and changed the design for the better: three isolated A/Bs
became a **role × harness grid**. Two roles across three harnesses, one harness (dsh) across two
roles, which buys an interaction the pairs could not see — dsh winning for both roles is a general
harness effect, dsh winning only for melchior is a **role × harness interaction**, which is this
project's own thesis one level up and the first evidence for it measured on something we did not
build.

The load-bearing control is the operator's own instruction: **all harnesses on MiniMax OAuth**.
Without it, "melchior codes better on dsh" measures DeepSeek's model and credits dsh's harness —
[R1](../refuted/R1-arm-M-as-falsifier.md) in a new costume. A harness that cannot hold the model
constant gets reported as *not tested*, never run with a footnote.

Phase 0 is a feasibility probe that installs nothing, dispatched to codex on a brief **compiled by
Bliss Point for codex**. Dogfooding it found [F4](../findings/F4-two-branches-each-assumed-the-other.md):
at `decomposition` 0.35 with `acceptance_binding` 0.9 — codex's designed shape — a Task carrying
subtasks rendered **no acceptance criteria at all, and raised no gap**. Both branches assumed the
other was carrying them. Every codex brief this project has compiled with subtasks on the Task has
been missing its definition of done. Fixed, regression test across all profiles, 42 green.

A second, milder instance surfaced immediately after: `escalation_explicitness` 0.45 dropped the
escalation triggers from the same brief. That drop is *correct* — selection is what the dial is for
— but the triggers here were safety stops (do not take pihole's port 53, do not fall back to the
7.4GiB laptop, do not copy an identity to the server). Overridden to 0.75 with the reason recorded.
**Open design question, not yet built:** a dial silently dropping a stop condition is doing its job
as specified, and the specification is wrong. The F4 invariant — no populated field leaves the Task
without appearing in the brief or raising a gap — would cover this too, and is now the next thing
to write.

## Sourcing closed: 45 candidates, and a rule the protocol was missing

Rounds 2 and 3 filled the four short categories. Totals: bugfix 27, feature 7, refactor 4,
investigation 4, under-specified 3 — **45 verified candidates for 20 slots**, every category
supplied.

Across the three rounds the tool caught 4 bad candidates and reading caught 4 more, which is the
number worth remembering: **mechanical admissibility is necessary and not sufficient**, and the
README now says so rather than implying the gate is the whole defence. The four the tool missed:
a behaviour-changing "refactor", a licence request filed as a vague bug, and two refactors that
were valid but degenerate.

Those last two produced **rule 7**. `psf/black` #5278 removes a duplicate list entry; #5277 removes
an unused constant. Real refactors, mechanically perfect, and useless — no brief format could
plausibly fail a one-line deletion, so all four arms pass and the task yields four identical
results. A **ceiling effect**, which the protocol had no rule against: rule 3 dropped tasks too hard
for the weak tier, and nothing dropped tasks too easy for any brief. That asymmetry is the more
dangerous one, because a ceiling effect burns identical budget while looking like a row of
successes.

Rule 7 reuses the arms already built: pilot **arm C** to confirm the task is not too hard, pilot
**arm R** — the floor — to confirm it is not too easy. `mixed` on the arm-R pilot is ideal. This is
the third protocol defect found by contact with real data rather than by reasoning about the design
([F3](../findings/F3-one-rule-for-five-ground-truths.md) was the second), and like the others it
was cheap to fix only because it was found before any runs were spent.
