# 2026-08-20 — day 2

**Settled D7.** Adopted the audit's positioning: task-contract compiler, headline is the refusal —
"it refuses to dispatch a brief the recipient cannot execute". Dials are the IR, linter is the
product. README, roadmap and repo description updated. Name and API unchanged.

**Pre-registered the 20-task A/B** on pi. Four information-matched arms built from one Task object
so only rendering differs. Wrote the power analysis honestly: n=20 binary resolves 25–30pp, so cost
and step metrics carry the finding and pass rate is directional only.

**Fixed a confound I built in.** "Tier A vs Tier B" conflated capability with vendor — an
interaction could have been one company's post-training preferring checklists wearing the costume of
a capability law. Now a 2×2 of {small, large} × {two families}: row effect means capability, column
effect means the profiles are vendor lore.

**Family bias.** Judging is a two-family panel with published inter-rater agreement; self-preference
is measured by having each judge score its own family blind, and if that bias exceeds the effect
being claimed, the judged portion is void. Objective metrics decide 16 of 20 tasks so judgement
touches as little as possible.

product could not lose to (refuted/R1). Replaced with a one-dial ablation across the render
threshold, scored on scope violations and steps. Published as Amendment 1 rather than a quiet
repair.
